## Jebakan baru: `/data/adb/service.d/*` read-only

Sayangnya `91_host_maintain.sh` (rotasi `/data/local/tmp/*.log` + prune darurat `dalvik-cache`) tidak bisa dipasang permanen. Context `u:r:magisk:s0`:

- `chmod` pada file existing **berhasil**
- `>` redirect, `>>` append, dan `touch` pada file baru **ditolak**: `can't create /data/adb/service.d/X: Permission denied`

Label folder `u:object_r:adb_data_file:s0`. Solusi: reinstall Magisk/ROM, atau pasang dari custom recovery tanpa batasan SELinux. Dampak kecil dalam kondisi sekarang: `sup-watch.log` 189KB (di bawah ambang 512KB), `dalvik-cache` hanya relevan saat free <300MB sedangkan sekarang free 2.48GB.

Verifikasi bahwa tidak ada kerusakan: `99_9router.sh` tetap 2253 byte utuh, file `zz_test.sh` dan `99_9router.sh.bak.20260927` yang sempat dibuat sudah dihapus.

## Jebakan update 9router (di luar cakupan repo ini, tapi biaya besar)

`/var/run/9router.pid` **tidak ditulis** oleh `supervisor.sh`/`99_9router.sh`. Akibatnya langkah "stop lama" di `update-9router.sh` yang relying-pidfile gagal → proses versi lama tidak mati, start baru kena `EADDRINUSE 0.0.0.0:20128`, dan HTTP 307 yang lolos verifikasi dijawab **proses versi lama** (file di disk sudah baru, RAM masih kode lama — kondisi tidak konsisten, tidak terdeteksi tanpa cek `ps`).

Fix: `pkill -9 -f custom-server; pkill -9 -f next-server` + guard `pgrep` sebelum swap, plus cetak `EADDRINUSE-recent` di langkah verifikasi. Recovery manual: `kill -9 <pid>` lalu start ulang. Catatan: `sh /data/adb/service.d/99_9router.sh` dari adb balas `Permission denied` — harus pakai `/data/adb/magisk/busybox sh ...`.
